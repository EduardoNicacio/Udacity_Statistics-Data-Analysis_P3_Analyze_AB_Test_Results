## 1. Elevator Pitch

**The Problem:** An e-commerce company has built a new page and wants to know whether to ship it, keep the old one, or run the experiment longer. The evidence is a single CSV of 69,889 users with three columns, and the notebook asks a fixed sequence of questions: describe the data, compute marginal and conditional conversion probabilities, then simulate the null hypothesis and decide. Two traps sit in the middle: conditional probabilities are easy to invert (`P(converted | treatment)` is not `P(treatment | converted)`), and the final answer depends on correctly reading a simulated p-value rather than on the arithmetic alone.

**The Solution:** The notebook was completed cell by cell, in the order the brief specifies, with comments explaining both what each block computes and why. Part I establishes the shape of the data (69,889 × 3, no missing values, `converted` as the only numeric column). Part II builds from the marginal conversion rate (13.05%) to group-conditional rates (control 10.53%, treatment 15.53%), country-conditional rates (US 13.28%, UK 12.51%, CA 12.53%), and a full country × group table computed with `groupby(...).mean().unstack()` and independently with per-cell queries. Part III sets both arms to the pooled null rate 0.130478, simulates 500 treatment-minus-control differences, plots the null distribution, and computes the p-value as the share of simulated differences at least as large as the observed +0.0501.

**The Result:** Treatment converts at **15.53%** versus **10.53%** for control — **+5.01 percentage points** — and the advantage holds in every country (US 15.8% vs 10.7%, UK 14.9% vs 10.2%, CA 15.4% vs 9.4%), so there is no meaningful interaction. The 500 null differences centre on **0.0000** with SD **0.0025**; the observed gap is ≈19.7 theoretical standard errors away, and **none** of the 500 simulations reached it, giving **p = 0.0000**. At α = 0.05 we reject H₀: the new page converts better, and the recommendation is to implement it. An independent standard-library re-implementation (`csv` only, no pandas) reproduced every reported count and rate: **33 checks, 0 failures**. The five-slide deck carries the same numbers and conclusion.

### Key Design Decisions

| Decision | Rationale |
| :--- | :--- |
| **Follow the cell order, never reorder** | The notebook's parts build on each other: the table in II j) needs the conditional rates, and III g) needs both the observed rates and `p_diffs`. Keeping the given order means every cell can assume exactly what the brief intended it to assume. |
| **Compute every rate from the 0/1 indicator's mean** | `df['converted'].mean()` is the probability of conversion; `converted == 1` counts divided by group size is the same quantity by hand. Using the mean keeps numerators and denominators implicit but consistent, and the independent verifier re-derived the raw counts to prove they agree. |
| **Compute the table two ways, then pivot** | The prompt supplies `query`-based and `groupby`-based methods for the US column. The completed cell uses `groupby(['group', 'country'])['converted'].mean().unstack()`, reindexes rows/columns to the prompt's order, and formats with `(table * 100).round(1)`; the US values 10.7/15.8 reproduce the pre-filled answers, which validates the pivot before the UK/CA results are trusted. |
| **Pool the two arms for the null rate** | Under H₀ both pages convert at the same true rate, so the best estimate from the observed data is the overall mean, 0.130478 — exactly what the pre-filled Part III a) cell sets. Using each arm's own observed rate would bake the effect into the null and make the test meaningless. |
| **Keep the brief's simulation code shape** | Parts III b)-e) are written with `np.random.choice([0, 1], size=n, p=[1-p, p])`, one draw per simulated user, rather than a binomial shortcut, because the exercise is explicitly about simulating individual conversions and comparing means. The 500-trial loop stores every difference and converts the list to `np.array` so the p-value and histogram operate on one collection. |
| **p-value as a proportion, not a formula** | The simulated p-value is `(p_diffs >= obs_diff).mean()`, the empirical share of null draws at least as extreme as the observed difference. No normal approximation is used, so no distributional assumption is smuggled in beyond the simulation model itself. |
| **Narrate comparisons in printed text, keep markdown intact** | The brief's markdown cells contain the questions; answers live in code comments and printed lines (plus the required written paragraph in III h). This keeps question and answer visually separate and leaves the provided markdown unaltered. |
| **Report the data's conclusion, not the expected one** | The task description anticipated a fail-to-reject outcome; the data produce p = 0.0000 in the opposite direction. The notebook, this note, and the deck all report what the data show, with the mismatch documented (Challenge 2). |

## 3. Analytical Principles in Practice

**A proportion is a mean, and a conditional proportion is a filtered mean.** `P(converted | treatment)` is computed by filtering first and averaging second — `df.query('group == "treatment"')['converted'].mean()` — never by dividing two unrelated counts. The group-conditional rates (10.53% and 15.53%) weight back to the overall 13.05% by group size, and the independent verifier checks that identity explicitly.

**Conditioning direction is labelled, not implied.** Part II asks for `P(converted | group)` and `P(converted | country)`; the written comparison names the direction every time. The retrospective question ("what share of conversions came from a group?") is a different quantity and is not what II b)-c) compute — keeping the bar in the text prevents that swap.

**Denominators travel with every rate.** The table is not just 10.7% / 15.8%; the underlying cells are 2,597/24,200 and 3,889/24,650, and the notes report them. A reader can re-divide any figure by hand, and the deck's table can be checked against the notebook's counts without rerunning anything.

**The null model is built before the test, and it is explicit.** Both arms are simulated from the same pooled rate because H₀ says the pages are interchangeable. The output shows the common rate, both sample sizes, the mean and SD of the null differences, and the observed difference on the same page, so the comparison the p-value makes is visible rather than asserted.

**Statistical significance is not practical significance, and the note says which is which.** The +5.01 pp gap is both statistically detectable (p < 0.05) and commercially meaningful for a conversion metric; the notebook reports the test result, while the recommendation ("implement the new page") is labelled as a practical judgement supported by the consistent country pattern, not as something the p-value alone proves.

**Multiple comparisons are acknowledged.** Three country-level comparisons plus the pooled comparison raise the chance that one looks extreme by noise; because all three point the same way and the pooled effect is ≈19.7 standard errors from zero, the conclusion is not sensitive to that concern — but the note records it rather than pretending a single test was run.

**Descriptive language, no causal overreach.** The data show that users *assigned* to treatment converted more often. They do not prove the page *caused* the lift for every segment, nor that the effect would persist after launch (novelty effects, seasonality, and selection are untested). The deck's "supports implementing" is deliberately weaker than "will increase revenue".

## 4. AI Collaboration Playbook

The deliverable is a notebook whose every figure is graded, plus a deck that must agree with it. The workflow therefore ran on an evidence hierarchy: **dataset → executed notebook → independent recomputation → presentation**.

1. **Plan before editing.** The full cell map (which of the 59 cells were empty, which were pre-filled, which were stubbed) was inspected first, and the plan for each part was agreed before a single cell changed. That prevented the common failure of "fill everything, then discover the pre-filled plot depended on a variable that was never defined".
2. **Treat the rubric as the acceptance test.** `docs/2. Rubric.md` lists functionality, coding practice, interpretation, value correctness, and the deck. Each was checked against the executed artifact — not against the intention behind the code.
3. **Execute, don't eyeball.** After the edits, the notebook was run top-to-bottom with a fresh kernel (`nbconvert --execute --inplace`), and the resulting file was parsed programmatically to confirm 28/28 execution counts, zero error outputs, and both figures embedded. Passing a visual read of the source is not the same as running it.
4. **Recompute independently.** A second implementation using only `csv` (no pandas) rebuilt every count and rate from the raw file and compared them against the notebook's printed text: **33 checks, 0 failures**. Agreement between two implementations is evidence; agreeing with oneself is not.
5. **Check the narrative against the artifact.** Every number in this document and in the README was taken from the executed notebook or the verifier's output. When the brief's expected conclusion disagreed with the computed p-value, the artifact won and the discrepancy was documented.
6. **Keep the deck and notebook in lockstep.** The deck's PDF text was extracted and compared with the notebook's figures (35,211 / 34,678, 15.5% / 10.5%, +5.0 pp, p = 0.0000, the 2×3 table). They match; the deck was not edited, per the project constraint.

The operating principle: **the executed output is the source of truth, and a second tool is the check on it.** The reviewing pass accepted no figure because the drafting pass asserted it; it recomputed it, and it recorded the places where the specification and the data disagreed instead of silently choosing one.

## 5. Evaluation & Verification Philosophy

**Executed outputs are the evidence.** Every reported figure — 69,889 rows, 9,119 conversions, 35,211/34,678 split, 3,650/5,469 converted, 0.130478, 0.105254, 0.155321, 0.050067, 0.049908, the nine table cells, 0.0000/0.0025, p = 0.0000 — was read from a completed run of the notebook, not estimated or recalled.

**Two implementations, different libraries.** The verification pass parsed the CSV with `csv.DictReader` and rebuilt the rates from integer counts; the notebook uses pandas dtypes, `query`, and `groupby`. A pandas-specific mistake (a mis-specified filter, an index alignment slip in `unstack`) cannot hide in both code paths at once.

**Identities are checked, not just values.** Beyond cell-by-cell equality, the verifier confirms that the group rates weight back to the overall rate, that the country rates weight back to the overall rate, that group and country counts each sum to 69,889, that every country × group cell sums to its group total, and that all table rates lie in [0, 1]. These identities catch transcription errors that a single formula would not.

**The p-value's meaning is tested by construction.** Because the p-value is `(p_diffs >= obs_diff).mean()`, it is reproducible from the stored `p_diffs` and the observed difference in the same notebook; the note also reports the theoretical null SE (0.002548) so a reader can see why 0 of 500 is expected rather than surprising.

**The verifier is code, and it can lie.** The 33 checks are deliberately simple string/number comparisons against the notebook's own printed text, which means they verify *agreement*, not *correctness of the specification*. That is why the numbers were also hand-checked against the raw counts shown in the table (2,597/24,200, 894/8,795, 159/1,683, 3,889/24,650, 1,302/8,756, 278/1,805) — a human-readable layer independent of both programs.

**Rounding is presentation only.** All arithmetic runs at full precision; percentages are formatted at output time with `:.1%` or `round(1)` after multiplying by 100. The table's 10.7 is a display of 0.107314, and the verifier compares the displayed one-decimal value against the independently computed one.

**Limits are disclosed.** Three columns mean no per-user deduplication and no landing-page integrity check; a convenience sample from one company means the effect is not automatically generalisable; and a simulated p-value of 0.0000 means "none of 500 draws", with a resolution floor of 1/500 = 0.002. All three caveats appear in §6 and §9 rather than being buried.

## 6. Challenges & Resolutions

### Challenge 1 - The file is a three-column extract, not the full event log

**What happened:** The course dataset link points to a richer file with `user_id`, `timestamp`, `landing_page`, `group`, `converted`, and `country`. The workspace copy has only `country`, `group`, and `converted` (69,889 rows). That is enough for every requested calculation, but two standard integrity checks become impossible: duplicate users cannot be detected, and users whose `landing_page` disagreed with their assigned `group` cannot be excluded or examined. Any silent duplication or assignment error in the original extraction is inherited here.

**Resolution:** The limitation is stated explicitly (README "Data sources", §9 "Data quality") instead of being ignored. All analysis is framed as conditional on this extract: the rates describe these 69,889 rows. Because every reported figure is a ratio of within-file counts, the missing columns cannot bias the arithmetic — only the generalisability and the purity of the sample.

### Challenge 2 - The expected narrative contradicts the computed p-value

**What happened:** The project brief's suggested interpretation anticipated `p_value > 0.05` and therefore "fail to reject H₀ — the control page is not statistically worse, keep the old page". The data say the opposite: treatment 15.53% against control 10.53%, a +5.01 pp gap, with **none** of 500 null simulations reaching it. Writing the expected narrative would have produced a notebook whose prose contradicted its own printed p-value.

**Resolution:** The answer in Part III h) reports the computed result — p = 0.0000, reject H₀ at α = 0.05, the treatment page converts at a significantly higher rate, implement it — and the mismatch between the template narrative and this dataset is documented in the README and here. The deck follows the data. This is the most important judgement call in the project: the grade rewards "correct interpretation of results", and a correct interpretation cannot ignore the result.

### Challenge 3 - The simulation is not bit-reproducible

**What happened:** The pre-filled setup cell calls `random.seed(0)`, but the simulations use `np.random.choice`; Python's `random` seed does not control NumPy's RNG. Re-running the notebook therefore yields different `treatment_converted`, `control_converted`, and `p_diffs` arrays, and slightly different printed values such as the single-trial difference.

**Resolution:** The pre-filled cell was deliberately left untouched, per the instruction not to alter provided cells, and the non-reproducibility is disclosed in the README instead of hidden. It does not affect the conclusion: the null SD is 0.0025, the observed gap is 0.0501 (≈19.7 theoretical standard errors), and every run of 500 draws returns p = 0.0000. The honest fix — adding `np.random.seed(0)` in a cell the candidate owns — is recorded in §10.

### Challenge 4 - A simulated p-value of zero is not literally zero

**What happened:** `(p_diffs >= obs_diff).mean()` returned 0.0000, which prints as a suspiciously perfect zero. With 500 simulations the smallest attainable non-zero value is 1/500 = 0.002, so "0.0000" means "none of 500 draws was this extreme", not "the probability is exactly zero". Reporting it as an exact zero would overstate the evidence.

**Resolution:** The interpretation explains that the p-value is the proportion of null simulations at least as large as the observed difference, that the observed gap is far outside the simulated range, and that the practical reading is "p < 0.002" at this simulation resolution. The analytic null SE (0.002548) is included in this note as corroboration, so the reader can see the result is not an artefact of 500 draws.

### Challenge 5 - "No interaction" is a description, not a test

**What happened:** The table shows treatment ahead in all three countries (US +5.05 pp, UK +4.70 pp, CA +5.95 pp), which the markdown prompt asks us to interpret as interaction or its absence. That pattern is visually consistent, but no formal interaction test was run, and CA's control arm has only 1,683 users — roughly a 2.3 pp standard error on that single cell — so "consistent" rests on effect sizes, not on a hypothesis test.

**Resolution:** The printed comment in II j) states the pattern as descriptive ("treatment beats control by roughly 4.7–6.0 pp in every country, so there is no strong evidence of an interaction") rather than as a tested claim; §9 repeats the boundary. A logistic regression with a `group × country` term is the correct formal follow-up and is listed in §10 as the main omitted standout.

## 10. Retrospective

### What I'd Do Differently

1. **Seed NumPy where it is allowed.** The pre-filled cell seeds Python's `random`, not `np.random`, so the simulation is not bit-reproducible. Adding `np.random.seed(0)` in the first candidate-owned cell (without editing the provided one) would make every printed simulated value reproducible while preserving the brief's code shape.
2. **Run the analytic test alongside the simulation.** A two-proportion z-test or a Wilson interval for each rate would quantify the same effect without simulation noise — for example, intervals around 10.53% and 15.53% — and would show that p = 0.0000 is a rounding of an astronomically small value, not a simulation artefact.

### Final Thoughts

The analysis itself is deliberately simple — filter, average, subtract, simulate — because the course is teaching judgement, not machinery. The judgement shows up in three places: choosing the pooled null rate so the test is honest; reading a simulated p-value as a proportion with a resolution limit rather than a magic number; and separating "the treatment converts more" from "ship it", which also depends on effect size, consistency across markets, and operational cost.

The most useful lesson came from the conflict between the expected and the observed. A notebook can be arithmetically perfect and still be wrong if its prose repeats a template instead of the result. Verifying every figure against a second implementation protected the numbers; reading the brief against the data protected the conclusion; and disclosing the dataset's limits protected the reader from over-reading a three-column extract. That combination — computed, cross-checked, and bounded — is what makes the deck's single recommendation defensible.
